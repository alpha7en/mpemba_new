## 3. Дерево решений

### Узел C-S (стратегический, требует научрука): ответ на CF-3
Вопрос: что делать с тем, что алгоритм оптимизирует время малого по величине эффекта?
- **Ветвь 1 — честный реframe (быстро, без новых результатов):** публикуем D(t\*), ΔD_max,
  долю пересечений; преимущество алгоритма подаём как перцентиль распределения
  преимущества случайных пар (наш контроль: 99.8-й перцентиль на 400 парах →
  расширить на 30k); «macroscopic» снимаем; в limitations прямо говорим: величина
  эффекта у поздних пересечений мала по построению, алгоритм оптимизирует время.
  Плюс относительная подача: ΔD/D(t\*) ≈ 7% в точке максимума преимущества —
  измеримо в нормированных распределениях интенсивности (проверить число!).
- **Ветвь 2 — модификация целевой функции (сильнее, новые результаты):** score с
  наблюдаемой величиной (например max_t ΔD или D(t\*) ≥ порог); пересчитать пару на
  демо-графе + бенчмарк (дёшево на 6×6). Риск: меняются флагманские числа; выигрыш:
  прямой ответ на «минимальные требования» рецензента.
- **Ветвь 3 (рекомендация):** 1 + лёгкая версия 2: основной текст — честный реframe;
  добавить анализ «а что если оптимизировать величину» (одна таблица: пара по новой
  целевой, её D(t\*), ΔD_max, t\*) как расширение Sec. 8 — показывает, что метод гибок.
Триггер выбора: обсуждение с научруком; вычислительно всё дёшево (6×6).
